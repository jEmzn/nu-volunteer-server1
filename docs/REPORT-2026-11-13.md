## ผลตรวจและการแก้: หมวด 1 backend และ data layer

รหัสตาม `REPORT.md`

### B5 `regCount` นับคนที่สแกนโดยไม่ได้ลงทะเบียน: จริง (server)

- **หลักฐาน:** `claims/credit-writer.ts` บวก `reg_count` ทุกครั้งที่สร้างแถว walk-in และ `roster/roster.ts` ลดค่าตอนยกเลิกหรือลบโดยไม่ดูว่าเป็น walk-in บนระบบจริง 8 จาก 11 กิจกรรมมีค่านี้รวม walk-in
- **แก้:** walk-in ไม่บวก `reg_count` การยกเลิกและการลบลดค่าเฉพาะแถวที่ไม่ใช่ walk-in
- **ข้อมูลเดิม:** นับ `reg_count` ใหม่บนระบบจริงด้วย SQL หนึ่งคำสั่ง แก้ 8 กิจกรรม ตรวจแล้วไม่เหลือค่าที่ไม่ตรง
- **หน้าจอ:** กิจกรรมที่ไม่มีผู้ลงทะเบียนแสดงเฉพาะจำนวนผู้ได้ชั่วโมง ไม่มี "จากผู้ลงทะเบียน" และไม่มี % (`ManageSummary.tsx`, `LiveCards.tsx` จาก upstream)
- **ผลข้างเคียงที่ตกลงแล้ว (ทางเลือก ก.):** walk-in ไม่กินที่นั่งของกิจกรรมที่จำกัดจำนวน "จำนวนรับ" จึงหมายถึงที่นั่งของผู้ลงทะเบียนล่วงหน้า
- **ไฟล์:** `src/modules/claims/credit-writer.ts`, `src/modules/roster/roster.ts`, `test/claims.test.ts`, `test/roster.test.ts`, `docs/API-CONTRACT.md`

### B4 `studentId` ในเครื่องไม่ตรงกับเจ้าของ token: จริง (web)

- **หลักฐาน:** `getStudent` จัดการเฉพาะ 404 กับ 401, `mine.ts` ตั้ง `failed` แล้วไม่มีที่ล้าง, `Claim.tsx` แปลง 403 เป็น "ไม่มีอินเทอร์เน็ต", `store.ts` ไม่ฟัง storage event ส่วน server ตอบ 403 ถูกต้องอยู่แล้ว
- **แก้:** `getStudent` ที่ได้ 403 ล้างตัวตนแล้วให้กรอกใหม่เหมือน 401, ล้าง `failed` เมื่อโหลดรายการกิจกรรมได้, tab อื่นที่เขียน `nuv:device` ถูกอ่านเข้ามาทันที (จาก upstream)
- **ไฟล์:** `src/data/remote.ts`, `src/data/mine.ts`, `src/store.ts`

### B3 Excel และตารางรายชื่อ: จริง (ทั้งสองฝั่ง)

- **หลักฐาน:** ไฟล์ Excel สร้างที่ server (`export/rows.ts`) ตารางบนจอสร้างที่เว็บ (`lib/excel.ts`) ทั้งสองที่เขียน "ไม่ได้ลงทะเบียน" และเวลายืนยันไม่มีวันที่
- **แก้:** สถานะเป็น "ได้ชั่วโมง (ไม่ได้ลงทะเบียน)", เวลายืนยันเป็น "14 พ.ย. 2569 00:12 น.", ขยายความกว้างสองคอลัมน์
- **แก้เพิ่มนอกรายงาน:** Excel เขียน "ไม่มีตำแหน่ง" เมื่อไม่มีระยะ ให้ตรงกับหน้าเว็บ (รายงาน 10 พ.ย. ข้อ 7 แก้ไว้เฉพาะฝั่งเว็บ)
- **ไฟล์:** `src/modules/export/rows.ts`, `test/unit.test.ts`, `test/roster.test.ts` / เว็บ `src/lib/excel.ts`

### B1 ผู้ดูแลได้ 401 แล้วถูก logout ทันที: จริง (web)

- **หลักฐาน:** `send()` ใน `remote.ts` เรียก `expireSession` ทันที แล้ว `store.ts` ล้างข้อมูลผู้ดูแล หน้าจึงเด้งไป login และฟอร์มที่กรอกค้างหาย
- **แก้ตามที่รายงานเสนอ:** เปิด dialog login ซ้อนบนหน้าเดิม เมื่อสำเร็จส่ง request เดิมซ้ำหนึ่งครั้ง ครอบคลุมทั้ง token ที่ server ปฏิเสธ และ token ที่หมดอายุระหว่างเปิดหน้าค้าง
- **รายละเอียดที่ตกลงแล้ว:** เติมชื่อผู้ดูแลให้ ผู้ใช้พิมพ์รหัสหน่วยงานเอง รหัสของหน่วยงานอื่นไม่รับ การแตะนอก dialog ไม่ทำให้ logout ต้องกด "ออกจากระบบ" เอง
- **ไม่เปลี่ยน:** เปิดแอปใหม่ด้วย token ที่หมดอายุแล้วยังไปหน้า login ตามเดิม เพราะไม่มีข้อมูลค้างให้เสีย
- **ไฟล์:** `src/data/session.ts`, `src/data/remote.ts`, `src/screens/sup/SignInAgain.tsx` (ใหม่), `src/App.tsx`, `src/data/remote.test.ts` (ใหม่)

### B2 หน้ารับชั่วโมงรอ GPS ทุกครั้ง: จริงบางส่วน (web)

- **หลักฐาน:** ขอ GPS เฉพาะกิจกรรมที่ `locMode` ไม่ใช่ `off` อยู่แล้ว และมี timeout 12 วินาทีอยู่แล้ว (`lib/geo.ts`) ที่ขาดคือการตรวจว่ามีชั่วโมงแล้วก่อนรอ GPS ซึ่งถูกถอดออกโดยตั้งใจเมื่อ 4 พ.ย. เพื่อลด request
- **แก้:** กิจกรรมที่ตรวจตำแหน่ง อ่าน `GET /activities/:id/credits/:studentId` หนึ่งครั้งก่อนขอ GPS ถ้ามีชั่วโมงแล้วแสดงผลทันที
- **ผลที่ตามมา:** การสแกนครั้งแรกของกิจกรรมที่ตรวจตำแหน่งมี request เพิ่ม 1 ครั้ง และได้คำตอบ 404 ซึ่งเป็นคำตอบปกติว่ายังไม่มีชั่วโมง
- **ไฟล์:** `src/screens/claim/Claim.tsx`, `docs/API-CONTRACT.md`

### B6 กิจกรรมทดสอบ 11 รายการบนระบบจริง: จริง

- **หลักฐาน:** `GET /activities` คืน 11 รายการ ทั้งหมดอยู่ใน "หน่วยงานทดสอบ"
- **แก้:** ลบทั้ง 11 รายการพร้อมการลงทะเบียน ชั่วโมง และแจ้งเตือนที่ผูกกับกิจกรรมนั้น server ไม่มี endpoint ลบกิจกรรม จึงลบด้วย SQL หลังสำรองข้อมูล
- **ลบเพิ่ม:** กิจกรรม 2 รายการและนิสิต 4 คนที่การทดสอบบนระบบจริงรอบนี้สร้างขึ้น
- **คงไว้:** หน่วยงานทดสอบ 3 หน่วยงาน (`DEV-ORG`, `DEV-ORG-2`, `DEV-ADMIN`) และนิสิตทดสอบเดิม 12 คน ตามที่ตกลงว่าลบเฉพาะที่รายงานระบุ
- **ผล:** `GET /activities` คืน `[]`

### B7 manifest ไม่มี icon และไม่มี favicon: จริง

- **แก้:** ใช้ไฟล์ใน `public/` ของ upstream (`favicon.svg`, `favicon-32.png`, `icon-192.png`, `icon-512.png`, `apple-touch-icon.png`, `manifest.webmanifest`)
- **ผลบนระบบจริง:** ทุกไฟล์ตอบ 200 ตรงชนิดไฟล์ และ manifest มี icon 3 รายการ
- **ที่ยังเหลือ:** path `/favicon.ico` เองยังตอบเป็น `index.html` แต่หน้าเว็บประกาศ icon ด้วย `<link>` แล้ว browser จึงไม่ต้องขอ path นี้

## ข้อจำกัดและเรื่องที่ยังเปิดอยู่

- **ยังไม่ merge และยังไม่ push:** ระบบจริงรันจาก branch `fix/report-2026-11-12` รอเจ้าของโปรเจกต์สั่ง
- **หน่วยงานจริงยังไม่มีในระบบ:** ตาราง `orgs` มีเฉพาะหน่วยงานทดสอบ 3 รายการ ต้องเพิ่มหน่วยงานจริงก่อนวันงาน และตัดสินใจว่าจะลบหน่วยงานและนิสิตทดสอบหรือไม่
- **server ไม่ได้รันเป็น service:** process ถูกเริ่มด้วยมือ ถ้าเครื่อง restart ต้องเริ่มใหม่เอง (`DEPLOY-CLOUDFLARE-TODO.md` ขั้นที่ 5 ยังไม่ได้ทำ)
- **ปิดกิจกรรมแล้ว server ยังรับ claim:** server ปฏิเสธหลัง "ส่งรายชื่อ" เท่านั้น การแก้ของ upstream ซ่อน QR บนจออย่างเดียว ไม่ได้แก้ในรอบนี้
- **ข้อความบนจอ QR หลังปิด:** ขึ้น "ส่งรายชื่อแล้ว ปิดรับชั่วโมง" แม้เพิ่งปิดและยังไม่ได้ส่งรายชื่อ เป็นข้อความของ upstream
- **นิสิตที่ถูกล้างตัวตนขณะอยู่หน้าแรก:** ถูกพาไปหน้า login ผู้ดูแล เพราะที่อยู่เปล่าของเว็บเป็นทางเข้าของผู้ดูแล เป็นพฤติกรรมเดิม หน้าอื่นพาไปหน้ากรอกรหัสนิสิตตามปกติ
- **ระบบข้อความฝั่งนิสิตถูกซ่อน:** upstream ตั้ง `MESSAGES_ON = false` route ยังอยู่และ e2e ของแชทยังผ่าน
- **`/favicon.ico`:** ยังตอบเป็น `index.html` ดูข้อ B7
- **`npm audit` ของ web:** รายงาน 2 รายการระดับ moderate ยังไม่ได้ตรวจว่ามาจาก dependency ใหม่หรือของเดิม
